What this shows

Trust first. The camera reading is acted on only after the Guardian's verdict; the second reading (a citizen running away at 18 km/h) lifts the suspect's score to 0.82.

A fake flood (d2): the Guardian marks the reading untrusted and the gate refuses the warning and the valve call. A layer down (d4): the Guardian stops answering, the Brain says so once and carries on with low-impact alerts only.

How the layers were made to fit

The Brain is built so that a partner can be replaced without touching the Brain: everything that depends on the Twin's naming, units or speed is configuration, not code, and every behaviour is agreed with the partners in the Interface Card.

One contract. The Data Dictionary messages, one example of each in contracts/examples/, JSON Schemas exported by one command, a four-edit rule for any change.

Trust is shared. The Guardian judges; the Brain scales trust by the verdict’s confidence and never learns from an untrusted reading.

One way out. Only the gate signs a call; agents get read-only tools; a valve or the grid needs a person.

Every layer runs alone. The mocks of the Twin and the Guardian ship with the Brain; brain conformance checks a real partner against the same contract.

Partners differ. brain onboard proposes renames and units for a Twin that names things differently and never edits config.

Failure is a state. A silent Guardian, a missing Twin, a spent model quota and an unknown alarm each have a named event and a defined behaviour.

Evidence, not claims. 1,064 tests, 4 Test Book scenarios, 50 held-out variants, a hash-chained log per run, and brain rehearse as the freeze check.

One command. make full builds one image and starts the Brain, both stand-ins, Neo4j and Qdrant.

2. The City Brain: one system, many parts that need each other

The Brain is a decision layer made of parts that each do one small thing and hand their result to the next: a prediction that raises attention, attention that recruits a team, a team that is handed a solver's answer, a gate that checks the team. No part is useful alone, and no part may act alone. This part explains what the parts are and, above all, how they are connected.

Figure 3. Three loops at three speeds. The loops are linked: an incident starts a task loop; a closed incident feeds the meta loop; a promoted lesson returns as a reflex.

Four rules that make the parts safe to connect

Trust before action. Every call names a trusted Guardian verdict that covers its evidence.

The gate is the only way out. Rules, agents and solvers propose; only the gate signs.

Code disposes. A model reasons, code checks (verify_case, verify_plan, verify_desk); a scripted team passes every scenario with no network.

Nothing is silent. A held action, a doubted value, an unknown alarm, a model outage: each is a named event.

The six departments

A department is three files (a manifest of detectors and actuators, reflex rules, a playbook), so a new kind of incident is a new pack, not new code. A desk can only advise neighbouring zones; it picks zone ids and never words.

TSYP14 · City Brain layerPart 2 · 2.1 Incident detection

2.1 Incident detection: five stages, each able to stop or flag

A reading becomes an incident only after it has been checked, believed, compared with what was expected, and matched to a department. At each stage something specific can go wrong, and the Brain says so instead of acting or staying silent.

Figure 4. The detection pipeline with one scenario for each thing a stage can stop. The scenarios are in the Test Book and reproduce from one command.

Prediction is part of detection

Each sensor learns its own normal (running mean and spread, taught only by trusted readings). A reading many spreads away is a surprise; the first is doubted and the reflex that would act on it is held until another reading agrees. Two sensors that should move together are watched through their difference, so a slow creep one of them makes is caught.

The same machinery looks ahead: a level tracker forecasts when a river reaches the flood line, which triggers an early public alert and raises the incident's attention. That alert is not sent on a doubted or disputed gauge.

Three things the Brain says instead of staying silent

Unknown alarm. A trusted camera anomaly that is neither a crime nor a collision, or a call in the category ‘other’, opens no incident; brain.human.needed says a person may be needed.

No procedure. A desk whose playbook has nothing for the incident type first reads the department’s other procedures; with none it sends nothing and asks for a person.

Stalled incident. An open incident with no new evidence for triage.stall_s asks for a person. The screen shows a red bar for each.

TSYP14 · City Brain layerPart 2 · 2.2 Decision method

2.2 Decision method: rules, agents and solvers, joined

The Brain does not use one method, it uses three and connects them. Rules answer at once. Agent teams (a model in each role, or a scripted stand-in) weigh the case. Solvers compute what judgement should not guess: which station, how few units, which cut, when the water arrives. The solvers run in code and their answers are written into the team’s brief, so a model that never calls a tool still reads them.

Figure 5. The decision pipeline. The reflex tier and the team tier run side by side; both end at the same gate.

Figure 6. Which tool serves which team. The solvers are on by default; each carries a certificate (status, objective, bound, hash of its inputs). A solver that fails leaves the old behaviour in place and says so.

TSYP14 · City Brain layerPart 2 · 2.3 How it picks an actuator

2.3 How the Brain picks an actuator, and why a call can still be refused

An actuator is chosen in three steps: the incident type decides which department may act and with what; the station or device is chosen (nearest, or the solver’s choice when incidents compete); and the gate decides whether the call may go. The Brain never calls the Twin directly.

Which actuator

IncidentActuator
crimedispatch_unit police (pursuit, contain), broadcast_alert, recall_unit
fire, accidentdispatch_unit fire or ambulance
jam, ambulance routeset_signal_phase green
floodbroadcast_alert, set_valve_state
overloadbroadcast_alert, set_grid_connection

Which station or device

Nearest by hop distance, excluding quarantined and reserved stations. When two or more incidents want the same kind of unit, the dispatch solver solves them together and its choice is used only if it saves cost: for two collisions the far ambulance goes to the first so the close one is free for the second (cost 2.8 against 4.2, checked against brute force by brain optimise-bench). With one incident the solver is not consulted at all.

A cascade analysis weighs what each cut would darken (a hospital counts 10), and the shed solver picks the cheapest set that removes the excess.

Figure 7. The gate. Every proposal from a rule, an agent or a solver meets the same eleven checks in order; a failed check is an event with its reason. A call the Twin never answered frees its key, so it can be retried; a Twin that did act answers duplicate.

The result of each call returns as a timeline event; a dispatched unit’s later unit_status readings close the incident, and an arrest or a stand-down recalls every unit still out.

TSYP14 · City Brain layerPart 2 · 2.4 Interconnection in action

2.4 The interconnection in action

The value of the design shows where several parts meet. Each column is a real scenario or a real failure, and each step is a different component handing its result to the next.

Figure 8. Three flows. Left: the solver, the corridor planner, the desk and the explanation all meet on one decision. Middle: a forecast, the gate, the triage and a desk meet on one river. Right: the model-health monitor, the teams and the screen meet on a failure.

Learning closes the loop

A closed incident is kept as an episode. brain sleep finds a plan the team made the same way more than once, rehearses it as a candidate reflex against the real team, and promotes it only if it passes every check. The promoted rule is a cache of a verified deliberation: it never reads whether a dispatch worked. The Academy tunes thirteen listed parameters one step at a time on synthetic streams and held-out seeds; the gate, contracts and suspect scoring are not on the list.

Explanation is part of the same wiring

Every decision, held action and incident can be explained: the events behind it, the knowledge it cited, the solver’s certificate, and counterfactuals proved by changing one input on the real gate. A signed bundle fails if one fact changes. The log is hash-chained and a run replays from its input journal.

2.5 Security: what is trusted, what is not, and what happens when it is wrong

Every input is hostile until it is checked, every model answer is a suggestion, and the only way out is one signed call that a person must approve when it is high-impact. The threats are mapped to MITRE ATT&CK for ICS and Enterprise and to MITRE ATLAS for the AI parts. Each attack below was run against the code (docs/SECURITY-MITRE.md).

Six trust boundaries and what guards each

BoundaryTrusted?Control
Twin to Brain: readingsNo, until checkedHMAC-SHA256 or Ed25519 over canonical JSON, key ids with expiry, a rising sequence number per sensor, schema and ranges; only allowlisted fields are kept; an optional freshness limit (twin.max_age_s)
Guardian to Brain: verdicts, retractionsYes, highlySchema check; the gate asks for independent trusted sources by impact level and a person for the highest; only the Guardian’s own token may retract a verdict
People and partners to the APIBy scopeScoped tokens off loopback (read, analyse, push, approve, admin), short-lived signed tokens that can be revoked, body and rate limits, a partner may push only into its own namespace and brain.* is refused
Brain to the language modelOutput is untrustedIds and fields are limited to safe characters before any prompt; read-only tools; models pick zones, never words; code verifies the answer; then the gate
Brain to Twin: actuator callsThe Twin must verifyEleven gate checks; each call is signed with its time and a one-time number; a valve or the grid needs a signed approval bound to the exact parameters, used once
Brain to its own diskMostlyHash-chained log with a signed head; learning only from trusted readings; self-tuning limited to a listed set of numbers, each with a range

What is not done

Verdicts are not signed. Fix: the readings’ key ring, or mutual TLS (guardian.tls, built).

No TLS by default. Signatures still protect readings and calls in transit.

Freshness limit off. Set it to a few times the live Twin’s interval.

Real partners not tried. Their checks of time and one-time numbers are untested.

Evidence: uv run brain redteam (24 attacks, all refused), brain security-check, scripts/security_poc.py (13 attacks in process), bandit clean, pip-audit, a software bill of materials. Threat list: docs/SECURITY.md; technique by technique: docs/SECURITY-MITRE.md.
