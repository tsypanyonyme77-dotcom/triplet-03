How the layers were made to fit

The Brain is built so that a partner can be replaced without touching the Brain: everything that depends on the Twin's naming, units or speed is configuration, not code, and every behaviour is agreed with the partners in the Interface Card.

One contract. The Data Dictionary messages, one example of each in contracts/examples/, JSON Schemas exported by one command, a four-edit rule for any change.

Trust is shared. The Guardian judges; the Brain scales trust by the verdict’s confidence and never learns from an untrusted reading.

One way out. Only the gate signs a call; agents get read-only tools; a valve or the grid needs a person.

Every layer runs alone. The mocks of the Twin and the Guardian ship with the Brain; brain conformance checks a real partner against the same contract.

Partners differ. brain onboard proposes renames and units for a Twin that names things differently and never edits config.

Failure is a state. A silent Guardian, a missing Twin, a spent model quota and an unknown alarm each have a named event and a defined behaviour.

Evidence, not claims. 1,112 tests, 5 Test Book scenarios, 50 held-out variants, a hash-chained log per run, and brain rehearse as the freeze check.

One command. make full builds one image and starts the Brain, both stand-ins, Neo4j and Qdrant.

2. The City Brain What should we do?

2.1 Role and goals

The Brain watches the Twin’s live readings, detects real incidents (crimes, fires, accidents, jams, floods, overloads), asks the Guardian whether each reading can be believed, decides the response and acts through the Twin’s actuators. It never acts on a reading the Guardian has not vouched for, and it never acts except through one checked door, the safety gate.

Figure 2.1. The Brain between its partners, one protocol on each link. Dashed cards are the other teams’ layers; the amber card is the gate, the only path to the city.

Trust before action. Every actuator call names a trusted Guardian verdict that covers its evidence (trust_ref).

One way out. Rules, agents and solvers only propose; the gate checks, signs and sends.

Code disposes. A model may reason, code verifies; a scripted team passes every scenario with no network.

Nothing is silent. A held action, a refused reading, an outage: each is a named event with its reason.

2.2 Architecture

One reading travels eighteen steps from the Twin to an action and an explanation. Each step is a small part with one job that hands its result to the next; each card names the technology that runs it and, in blue, the brain function it is modelled on (brain-inspired engineering, not a model of a brain).

Figure 2.2. From a reading to a decision. Amber arrows are the way out: reflex proposals reach the gate at once, the team’s plan follows and meets the same gate. A plan the team makes the same way twice returns as a reflex after sleep.

Incident detection

Perception checks the contract version, the HMAC signature, the sequence number (replay) and value ranges; a refusal has a code. The Guardian’s verdict (2 s deadline) decides whether the reading may count. Forward models learn each sensor’s own normal from trusted readings only: a reading many spreads away is a surprise and the reflex it would trigger is held until a second source agrees; a Kalman tracker forecasts when a river reaches the flood line. Triage runs the six departments’ detectors to open or join an incident, and the workspace gives two seats of attention by severity, trust, surprise and urgency.

Instead of staying silent the Brain says brain.human.needed for an alarm no department knows, an incident with no procedure, or an incident that stalls.

Decision method: rules, agents and solvers, joined

Rules (13, in six packs) answer in milliseconds with no model. Agent teams weigh the case: for Police an Analyst, a Tactician and a Chief on LangGraph (Groq models with --llm, a scripted stand-in otherwise or when the model fails); the other departments use a two-role desk. Solvers compute what judgement should not guess (OR-Tools min-cost flow for dispatch, CP-SAT for a perimeter and for load shedding, Dijkstra for a green corridor, Kalman for the flood forecast). They run in code before the agents and their answers are written into the brief, so a model that never calls a tool still reads them.

Code then verifies the agents’ plan (verify_case, verify_plan, verify_desk) before it reaches the gate.

TSYP14 · City Brain layerPart 2 · 2.2 Architecture · how it picks an actuator

2.2 Architecture (continued): how the Brain picks an actuator

Three steps: the incident type decides which department may act and with which actuator; a solver or the nearest free station picks the device; the gate decides whether the call may go. The Brain never calls the Twin from anywhere else.

Figure 2.3. The planning graph for one incident (LangGraph): solve and deliberate in parallel, keep the better plan, pause for a person on a valve or the grid, checkpoint to SQLite so a run resumes and replays.

Which station or device

Nearest free station by hop distance, never a quarantined or reserved one (scenario T16: the Guardian quarantines a station, the gate refuses it with reason quarantine and another is sent). When two incidents want the same kind of unit, the dispatch solver solves them together and its choice is used only if it saves cost: for two collisions the far ambulance goes to the first so the near one is free for the second (2.8 against 4.2).

Which cut, which signal

A cascade analysis weighs what each grid cut would darken (a hospital counts 10) and the shed solver picks the cheapest set that removes the excess. A corridor holds the signals on an ambulance’s route green. A dispatched unit’s unit_status readings close the incident; an arrest recalls every unit still out.

Figure 2.4. The safety gate. Every proposal, from a rule, an agent or a solver, meets the same eleven checks in order; the first that fails stops the call and is logged with its reason. A repeated call returns duplicate from the Twin.

2.3 Tech stack and why

Standard, well-known parts, each with one job. The stack runs offline on one laptop: the embedding model is baked into the image, the screen loads nothing from the internet, and a model outage only changes who reasons.

2.5 Security measures

Every input is hostile until checked, every model answer is a suggestion, and the only way out is one signed call that a person approves when it is high-impact. Threats are mapped to MITRE ATT&CK for ICS and to MITRE ATLAS for the AI parts (docs/SECURITY-MITRE.md).

Evidence. brain redteam: 24 attacks, all refused (re-run for this report). A partner’s bad message is answered with a stable code and a sentence (signature_invalid, replay_or_out_of_order, value_invalid…) and shown on the timeline. A silent Guardian gives no verdict, so nothing it has not judged is acted on (T15): the Guardian’s fail-safe rule, enforced on the Brain’s side too.

2.6 Known limitations

No joint run with the real Twin yet. End to end only against mocks; against the live Guardian, the fake and real flood and T16 (logs/t16-live-guardian-*.log).

The mock Guardian is scripted. T13 and T16 show what the Brain does given a verdict, not whether a real Guardian would give it.

Our mock’s contract does not sign verdicts. The Guardian team’s 1.0 does, and the Brain checks it.

Tuned on stand-ins. Which sensors move together, and whether same-zone sensors are independent, wait for the real Twin’s data (docs/TWIN-HANDOVER.md).

TLS and the freshness limit are off by default. Signatures still protect readings and calls; set twin.max_age_s on the live Twin.

One dispatch per incident at the Guardian. Its auditor refuses a second dispatch for one incident (duplicate_dispatch), so T14’s perimeter units would be refused. To agree: a duplicate is the same incident and station.

Guardian alerts are not read. An actuator it flags unreliable reaches the Brain through the containment list, which the gate obeys; compromised_twin does not.
